# 05 — UI

## 1. Input form

```
┌────────────────────────────────────────────┐
│  Race Readiness Check                      │
│                                            │
│  Battery voltage      [ 4.10    ] V        │
│  Battery current      [ 0.5     ] A        │
│  Battery temperature  [ 25      ] °C       │
│  Charging duration    [ 60      ] min      │
│                         = 3,600 s          │  ← live conversion hint
│                                            │
│                [ Submit ]                  │
└────────────────────────────────────────────┘
```

- Numeric inputs with units shown next to each field, followed by a **Submit** button. Decimals and negative values are allowed, except for duration.
- A live hint under duration shows the converted seconds.
- Submit is disabled until all fields are valid. Errors appear inline under the field (see [01-requirements.md](01-requirements.md) §1.1).
- While the check runs, show a spinner and stage progress: "Overcharge ✓ → Thermal … → Prediction".

## 3. Result — DO NOT PROCEED

Red banner. One card per failed rule, each in the same fixed format: reason, recorded value(s), hazard threshold(s), and the stage that failed. Rule IDs (R1–R6) and reason codes (for example `OVERCHARGED`) are internal. They are **not shown** on screen; only the plain-language reason is. Thresholds are written as the **failing condition**, matching the brief's example (for example, "battery voltage hazard threshold: > 4.2 V"). The exception is Stage 3: the prediction card shows the predicted efficiency as the recorded value and the minimum as **required to pass** (for example, "required to pass: predicted efficiency ≥ 70 %").

```
┌──────────────────────────────────────────────────────────────┐
│  ⛔  DO NOT PROCEED                                           │
│                                                              │
│  Stage 1: Overcharge                                         │
│  Reason: Battery already overcharged                         │
│    Recorded (input):  battery voltage 5.00 V,                │
│                       battery current -1.20 A                │
│    Hazard threshold:  battery voltage > 4.2 V AND            │
│                       battery current < 0 A                  │
│                                                              │
│  Agent summary: The battery shows negative current above the │
│  4.2 V limit, so it is already overcharged. Do not enter.    │
└──────────────────────────────────────────────────────────────┘
```

Example with several thermal failures (`T_t = 30 °C`, duration 1 min = 60 s):

```
⛔ DO NOT PROCEED
 Stage 2: Thermal
 • Thermal stress from battery charging is at high risk
     Recorded (calculated):  dT/dt = 0.08333 °C/s   ((30 − 25) / 60 s)
     Hazard threshold:       dT/dt > 0.03 °C/s
 • Heat is increasing at a very fast rate while the battery charges
     Recorded (calculated):  d²T/dt² = 0.001389 °C/s²   (0.08333 / 60 s)
     Hazard threshold:       d²T/dt² > 0.0005 °C/s²
 • Heat exposure to the surrounding environment is too high
     Recorded (calculated):  T_chem = 5.00 °C   (max(0, 30 − 25))
     Hazard threshold:       T_chem > 0.3 °C
```

Example with a Stage 3 prediction failure. Stages 1 and 2 passed, the model passed its quality gates, and the predicted efficiency is 65 %:

```
⛔ DO NOT PROCEED
 Stage 3: Prediction
 • Predicted efficiency is too low, so the car cannot proceed into the race
     Recorded (calculated):  predicted efficiency = 65.00 %   (XGBoost model v1)
     Required to pass:       predicted efficiency ≥ 70 %
```

### 3.1 Message templates

The Rule and Code columns tell the code which template to use. Only the Message column is displayed.

| Rule | Code | Message |
|------|------|---------|
| R1 | `OVERCHARGED` | **Battery already overcharged.** Battery voltage: `{V} V`, battery current: `{I} A`. Battery voltage hazard threshold: `> 4.2 V`. Battery current hazard threshold: `< 0 A`. (Unsafe when both are true.) |
| R2 | `HIGH_DTDT` | **Thermal stress from battery charging is at high risk.** dT/dt: `{dTdt} °C/s` (calculated from T = `{T_t} °C`, T0 = 25 °C, t = `{t} s`). Hazard threshold: `> 0.03 °C/s`. |
| R3 | `HIGH_D2TDT2` | **Heat is increasing at a very fast rate while the battery charges.** d²T/dt²: `{d2Tdt2} °C/s²`. Hazard threshold: `> 0.0005 °C/s²`. |
| R4 | `HIGH_TCHEM` | **Heat exposure to the surrounding environment is too high.** T_chem: `{Tchem} °C` (= max(0, `{T_t}` − 25)). Hazard threshold: `> 0.3 °C`. |
| R5 | `LOW_EFFICIENCY` | **Predicted efficiency is too low, so the car cannot proceed into the race.** Predicted efficiency: `{eff} %` (XGBoost model v`{version}`). Required to pass: `≥ 70 %`. |
| R6 | `MODEL_NOT_VALIDATED` | **Efficiency model not validated, so the race cannot be cleared.** Tolerance accuracy: `{tol} %` (needs > 80 %), R²: `{r2}` (needs > 0.90), train − test R² gap: `{gap}` = `{fit_status}` (needs 0.05 ≤ gap < 0.1). |

Threshold values in messages are filled in from `thresholds.yaml` at runtime, not hard-coded. Calculated values are shown to at least 4 significant figures, so that a small value like `0.000167` is not rounded to `0`.
